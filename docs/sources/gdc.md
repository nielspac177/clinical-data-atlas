# NCI Genomic Data Commons (GDC)

- **Source id:** `gdc` · **Harvester:** `atlas/harvest/gdc.py` · **Normalizer:** `atlas/normalize/gdc.py`
- **Endpoint(s):** `GET https://api.gdc.cancer.gov/projects?size=100&from=0&expand=summary,summary.data_categories,summary.experimental_strategies,program&format=json`, paged defensively via `from=` against `data.pagination.total` · **Auth:** none · **Politeness:** 350 ms/host (`atlas.config.POLITE_DELAY`), UA `clinical-data-atlas/<version> (+repo; mailto:...)` · **robots.txt:** none (`https://api.gdc.cancer.gov/robots.txt` → `404`, verified live)
- **Verified:** 2026-08-22 · **Count:** 93 projects (fits in a single `size=100` page: `data.pagination` was `{"count": 93, "total": 93, "size": 100, "from": 0, "pages": 1}`) · **Deviation from brief:** the endpoint, params, and response shape all matched the brief and `m1-shared-context.md` exactly; `conditions`' study-title heuristic was later broadened past the brief's literal 5-keyword list under post-review controller ruling R13 (fix round 1/5) — see Quirks.

## Quirks

- **One page in practice, but paged for real.** All 93 projects come back in one `size=100` request today. The harvester still pages via `from=` (advancing by however many hits the last page returned) against `data.pagination.total`, purely so a future project count above 100 doesn't silently drop projects — this path is covered by a synthetic two-page fixture in `tests/test_harvest_gdc.py` since the real API never exercises it right now.
- **`dbgap_accession_number` is sometimes absent, not just `null`.** Most hits carry a project-level `dbgap_accession_number` key (string or explicit `null`), but at least one live project (`ALCHEMIST-ALCH`) omits the key entirely. `access_notes`'s phs lookup uses `.get(...)` on both the project- and program-level fields for exactly this reason.
- **`released`/`state` don't always agree with `releasable`.** The brief's inclusion rule is `released and state == "open"`; `releasable` (also present on every hit) is a third, separate flag the brief does not reference and this normalizer ignores. Live example: `ALCHEMIST-ALCH` has `releasable=false` but `released=true, state="open"` — included. Live example of real exclusion: `CGCI-BLGSP` has `released=true` but `state="submitted"` — excluded with `reason="not_released"` (the same reason string is used regardless of which of the two conditions failed; the brief specifies one reason, not two).
- **The study-title name heuristic (ruling R13).** `conditions` treats a project `name` as a plain disease phrase — and uses it as the sole `Condition` — only when it is *both* free of every keyword in the word-boundary, case-insensitive pattern `MATCH|Arm|Characterization|Phase|Study|Trial|Enrichment|Identification|Sequencing|Consortium|Program|Project|Initiative|Cohort|Screening|Pilot` *and* at most 6 words long; anything else falls back to one `Condition` per `disease_type` entry. This supersedes Task 1.3's original mapping (a plain, non-word-bounded 5-keyword substring search: `MATCH|Arm|Characterization|Phase|Study`), which post-review fix round 1/5 found let a real live project through: `ALCHEMIST-ALCH` ("Adjuvant Lung Cancer Enrichment Marker Identification and Sequencing Trial") contains none of the original five keywords and was shipping its full trial title as a bogus `Condition`. The broadened keyword list and the 6-word cap both independently catch it now (it is 9 words either way, and also now matches "Enrichment"/"Identification"/"Sequencing"/"Trial"); the length cap additionally catches any future long title that happens to dodge every keyword, and the switch to word-boundary matching stops false positives the old plain substring search was exposed to (e.g. "Army" no longer matches "Arm", "Matcha" no longer matches "MATCH"). Regression-tested in `tests/test_normalize_gdc.py` against the real `ALCHEMIST-ALCH` fixture (`disease_type=["Not Reported"]` → `Condition(label="not reported")`, never the trial title) and against `TCGA-GBM` ("Glioblastoma Multiforme", short and keyword-free → `Condition(label="glioblastoma")` via `CONDITION_ALIASES`).
- **`summary.file_count`/`summary.file_size` are content, not volatile.** They change as GDC ingests more files for an already-released project, but per the verified-endpoint notes they're treated as real content changes (not stripped before hashing), so a project picking up new files between refreshes correctly shows up as changed in `data/raw/gdc/manifest.json`.
- **Fixture selection.** `tests/fixtures/gdc/` was captured with exactly one live call (`size=100&from=0&expand=...&format=json`, the real production request — see `tests/fixtures/gdc/listing.json`'s `pagination` block, preserved untouched from that call even though `hits` was trimmed to 5). The 5 originally selected projects are `TCGA-LUAD`, `TCGA-GBM`, `TARGET-AML`, `MATCH-S1`, `CGCI-BLGSP` — chosen instead of a strict first-5 slice specifically to cover, with real data rather than synthetic payloads: the mandatory `TCGA-GBM` + a `TARGET` project, a `CONDITION_ALIASES` hit ("glioblastoma multiforme" → "glioblastoma"), the `disease_type`-based conditions branch (`MATCH-S1`), the `pediatrics` domain (`TARGET-AML`), and a real (not fabricated) `not_released` exclusion (`CGCI-BLGSP`, `state="submitted"`). A 6th, `ALCHEMIST-ALCH`, was added in the ruling-R13 fix round (fix round 1/5) specifically as a real regression fixture for the study-title heuristic fix above; it comes from the very same original live capture rather than a second network call. `primary_site`/`disease_type`/`data_categories`/`experimental_strategies` lists longer than 5 entries were truncated to their first 5, verbatim, per the fixture-size guidance in `m1-shared-context.md`; a few mapping branches those six don't happen to hit in their first 5 entries (e.g. `Proteome Profiling`, program `CCDI`, a project with no dbGaP accession anywhere) are covered instead by small hand-built envelopes in `tests/test_normalize_gdc.py`.
- **Minor fix-round hardening (fix round 1/5, same review as ruling R13).** `summary` omits its "with `<N>` cases" clause entirely when `summary.case_count` is null (it previously would have rendered the literal string "with None cases"). `keywords` is now deduplicated (first occurrence wins) and drops empty strings (a missing `experimental_strategy` or a blank `program.name` no longer shows up as a bare `""` keyword). `probe()` now raises `AssertionError` — not an uncaught `AttributeError` — when `hits[0]` in the response isn't a dict at all.

## Field mapping

| raw | canonical | transform |
|---|---|---|
| `project_id` | `id` | `f"gdc:{project_id}"` |
| `project_id` | `source_native_id` | verbatim |
| `project_id` | `url` | `f"https://portal.gdc.cancer.gov/projects/{project_id}"` |
| `name`, `project_id` | `name` | `f"{name} ({project_id})"` |
| `name`, `program.name`, `summary.case_count`, `primary_site`, `summary.data_categories` | `summary` | `"<name>: <program> project in the NCI Genomic Data Commons with <case_count> cases; primary sites: <sites>; data: <top 3 data categories by case_count>."`, trimmed to ≤40 words via `io.first_words`; the `with <case_count> cases` clause is omitted entirely when `case_count` is null |
| `released`, `state` | record inclusion | keep only `released and state == "open"`; else `Excluded(reason="not_released")` |
| `summary.case_count` | `sample_size` | verbatim (nullable) |
| `summary.case_count` | `sample_unit` | `"cases"` when `case_count` is not null, else null |
| `summary.data_categories[].data_category` | `modalities` (part 1) | `Clinical`/`Biospecimen` → `clinical_tabular`; `Sequencing Reads`/`Simple Nucleotide Variation`/`Copy Number Variation`/`Structural Variation`/`Somatic Structural Variation`/`Combined Nucleotide Variation`/`DNA Methylation` → `genomics`; `Transcriptome Profiling` → `transcriptomics`; `Proteome Profiling` → `proteomics`; anything else contributes nothing |
| `summary.experimental_strategies[].experimental_strategy` | `modalities` (part 2) | `Tissue Slide`/`Diagnostic Slide` → `pathology`; result deduplicated and ordered per `vocab.MODALITIES` |
| `name` (disease phrase: ≤6 words AND free of every keyword in `MATCH\|Arm\|Characterization\|Phase\|Study\|Trial\|Enrichment\|Identification\|Sequencing\|Consortium\|Program\|Project\|Initiative\|Cohort\|Screening\|Pilot`, word-boundary — ruling R13) | `conditions` | `[Condition(label=alias(name.lower()))]` |
| `disease_type[]` (when `name` fails either the keyword-free or the ≤6-word test above) | `conditions` | one `Condition(label=alias(d.lower()))` per entry |
| `primary_site[]` | `keywords` (part 1) | verbatim entries |
| `program.name` | `keywords` (part 2) | verbatim |
| `summary.experimental_strategies[].experimental_strategy` | `keywords` (part 3) | verbatim, every strategy (including ones already mapped to `pathology`); the combined list is deduplicated (first occurrence wins) and empty strings are dropped |
| `program.name` | `domains` | `["oncology"]`, `+ "pediatrics"` when `program.name` is `TARGET` or `CCDI` |
| — | `access` | fixed `"open"` |
| — | `access_tiers` | fixed `["open", "application"]` |
| `dbgap_accession_number` (project-level, falls back to `program.dbgap_accession_number`) | `access_notes` | `"Open tier: clinical, biospecimen, masked somatic mutations, expression. Controlled tier via dbGaP <phs>."`, or the same sentence without a `<phs>` when neither level reports one |
| — | `license` | fixed `null` |
| — | `species` | fixed `"human"` |
| — | `institutions`, `authors`, `papers`, `related` | fixed `[]` |
| — | `countries` | fixed `[]` — the API never states a collection country, so `"US"` is deliberately *not* assumed |
| — | `years` | fixed `{}` (both `start`/`end` null) — not reported |
| — | `record_status` | fixed `"active"` |
| whole hit (`payload`) | `provenance.raw_hash` | `io.content_hash(payload)` |
| — | `provenance.harvested_via` | `"api:gdc-projects"` |
