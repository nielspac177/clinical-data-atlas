About & methods

A map of the clinical data landscape

The Clinical Data Atlas is a living catalog of open and gated clinical and neuroscience datasets, described in one schema, rebuilt from its sources every month, and published from a single public repository.

What this is

Finding clinical data is mostly a memory problem: the datasets exist, but they are scattered across repositories, journal descriptors and institutional portals, each with its own vocabulary for the same ideas. The atlas normalizes all of it into one record shape — what the dataset contains, which modalities and conditions it covers, who collected it, where, when, and on what terms you can get it — and then gives you two ways to move through the result: a 3D graph of how sources, modalities, conditions and institutions connect, and a filterable table over the same records.

The data files are the product; this site is a view of them. Every record, the raw responses it was built from, and the code that did the building live in the repository, so any number in the graph can be traced back to the API response that produced it.

What this isn’t — metadata only

  • It never hosts or redistributes dataset contents. No images, no waveforms, no patient records — not even copies of small ones. Each entry links out to the source’s own page, and that is where access happens.
  • It is not an access broker. Gated resources are described from their public documentation; the atlas cannot grant, speed up, or vouch for access to any of them.
  • It is not a review or a ranking. Inclusion is not an endorsement, and the atlas makes no claim about a dataset’s quality, validity, or fitness for your question.
  • It is not a substitute for the source. Always read a dataset’s own documentation, license, and data use agreement before planning work around it.

Sources & methods

The pipeline runs in four stages: harvest (talk to a source’s API and cache the raw response), normalize (map that response into the canonical schema), enrich (classify domains, modalities and conditions, write the short summary, resolve institutions and de-duplicate), and graph (derive the nodes, edges and search index this site loads).

The current release harvests four repositories:

  • OpenNeuro — public GraphQL API; BIDS neuroimaging datasets with their snapshot metadata.
  • PhysioNet — published-projects API; physiological signal, waveform and clinical databases, with the access policy the project itself declares.
  • NCI Genomic Data Commons — projects API; cancer genomics programs with case and file summaries.
  • The Cancer Imaging Archive — the public NBIA services for collections, modalities and body parts, joined to DataCite for descriptions, licenses and DOIs.

Journal data descriptors and a hand-written curated tier (for resources with no API at all — NHANES, ADNI, PPMI and the like) come in later phases.

Every request identifies itself with a descriptive User-Agent and a contact address, is rate-limited per host, backs off on errors, and respects robots.txt; a source that disallows automated access is documented rather than scraped. Raw responses are committed to the repository, so each record carries real provenance: how it was harvested, the date it was first seen, and the date a refresh last confirmed it still exists.

Enrichment is rules-first, with an LLM used only where the rules can’t decide — classification and the short summary. Each record records the origin of each enriched field, and no value is ever invented: if a source doesn’t report a sample size, the field is explicitly null rather than guessed. Per-source endpoint notes, quirks, and verification dates are kept in docs/sources.md.

The schema

One record shape covers every source. It is defined once as a pydantic model, and the human and machine-readable copies (docs/schema.md, docs/schema.json) are generated from it, so they cannot drift.

Seventeen clinical domains

Domains are the color axis of the graph. A dataset can carry more than one; other is a deliberate catch-all rather than a dumping ground for anything unclassified.

  • Neurology
  • Psychiatry
  • Neuroscience
  • Cardiology
  • Oncology
  • Pulmonology
  • Critical care
  • Surgery
  • Pediatrics
  • Obstetrics & gynecology
  • Infectious disease
  • Endocrinology & metabolism
  • Gastroenterology & hepatology
  • Nephrology & urology
  • Musculoskeletal
  • Public health
  • Other

Alongside them: 33 modalities (imaging, electrophysiology, omics, records and tabular data), conditions resolved against MeSH where possible, institutions resolved against ROR, countries as ISO two-letter codes, species, sample size with its unit, years of collection, license, authors and related papers.

Five access tiers

access is the least-restrictive tier at which substantive data is usable. Where a source offers several paths, the extra tiers are listed separately and explained in a note; where its own signals conflict, the atlas resolves to the more restrictive reading.

Open
Downloadable with no account and no agreement beyond the dataset’s license.
Registration
A free account, or a click-through agreement, and then immediate access.
Credentialed
A verified identity plus human-subjects training and a signed data use agreement — PhysioNet’s credentialed databases are the canonical example.
Application
A written request reviewed by a data access committee, which can decline. Most controlled-access genomic and cohort data sits here.
Purchase
A fee or a purchased license, sometimes on top of an agreement.

How to cite

If the atlas helped you find or characterize datasets, cite it — and cite each dataset you actually use in the way its own source asks. The CITATION.cff file in the repository is the authoritative, machine-readable version and carries the current release number.

@software{clinical_data_atlas,

Propose a dataset, or correct one

Missing datasets and wrong fields are both bugs, and both are fixed the same way: open an issue. The forms are schema-shaped, so what you fill in maps directly onto a record.

  • Propose a dataset — for a resource the atlas doesn’t know about yet.
  • Correct a record — for a dataset that is here but described wrongly, or has moved, or is gone.

Corrections that belong upstream get fixed in the harvester or the normalization rules rather than by hand-editing the catalog, so the fix survives the next refresh.

Licenses

  • Code — the pipeline and this site are MIT.
  • Catalog metadata — the records under data/ are CC BY 4.0. Reuse them freely, with attribution, so provenance stays attached.
  • The datasets themselves — not the atlas’s to license. A record’s license field reports what its source states; it grants nothing and can be out of date. The source’s own terms always govern.

Disclaimer

This catalog is assembled automatically from third-party APIs and public documentation, with machine assistance for classification and summaries. It will contain records that are incomplete, stale, or wrong. Verify anything that matters against the source before you rely on it — especially access terms, licensing, and anything bearing on human-subjects protections.

The atlas is an independent project. It is not affiliated with, endorsed by, or speaking for any of the repositories, institutions or funders it catalogs, and nothing here is legal, regulatory, or clinical advice.

Keyboard use & accessibility

The graph is a visual complement; search and the Table view are the keyboard-accessible path to the same records. Nothing is reachable only through the 3D scene: every dataset the graph can show is in the table, with the same fields and the same detail panel.

  • / focuses the search box from anywhere on the page.
  • Esc closes the search results, then the detail panel.
  • The theme follows your operating system by default; the toggle in the header overrides it and is remembered on this device.
  • Counts and filter results are announced in a polite live region, so a screen reader hears what changed without losing your place.
  • Motion is reduced automatically when your system asks for it: camera moves become cuts.

Found something that doesn’t work with your setup? That is a bug worth reporting — open an issue.
